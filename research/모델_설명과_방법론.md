# Context Guard V2: 모델 설명과 방법론

## 목표와 범위

LLM이 사용자의 낯선 표현·상황·가치 기준을 익숙한 지배적 범주로 성급히 치환하는 출력을 줄이는 것을 목표로 한다. ‘지배적인 맥락’ 전체를 자동 판별하는 분류기는 아니다. 실제 구현은 입력에 명시된 의미와 생성 답변의 관계를 점검하는 범위로 제한된다.

모델 가중치 θ는 고정된다. Qwen2.5-Instruct를 WebLLM에서 실행하고 추론 절차를 바꾼다. 사전학습·미세조정·DPO·RLHF·독립 critic 학습·새 언어 잠재공간 학습은 수행하지 않았다. 따라서 ‘새 기반모델’보다 ‘기존 LLM에 적용한 맥락 보존 추론 시스템’이 정확한 설명이다.

## 입력

사용자는 질문 Q, 상황 C, 보존할 용어와 의미 T를 작성한다. 이를 프로그램이 원문 그대로 anchor 목록 A로 만든다. 질문은 Q, 맥락은 C, 용어는 T1·T2…라는 ID를 갖는다. 모델이 원문을 먼저 요약하거나 사용자 소속 집단을 추정하지 않는다. 사용자가 제공한 사실 주장은 독립적으로 검증된 사실과 구분한다.

예: `품앗이 = 금전 환산을 전제로 하지 않는 상호 노동과 돌봄`. 이 정의는 해당 사용자 과제에서의 의미이지, 품앗이에 관한 유일한 학술 정의가 아니다.

## 처리 과정

1. **초안 생성**: 기본 모델에 동일한 질문·맥락·용어를 전달해 답변 d를 만든다. 비교 조건 모두 같은 입력과 생성 설정을 사용한다.
2. **원문 근거 점검**: 모델이 d와 A를 비교해 문제 항목을 제안한다. 유형은 의미 치환, 기준 부과, 맥락 누락, 근거 없는 확정이다. 각 항목에는 초안 인용, 원문 anchor ID와 인용, 설명, 수정 제안이 있다.
3. **프로그램 검증**: 초안 인용이 d의 정확한 부분 문자열인지, 원문 인용이 지정된 A의 정확한 부분 문자열인지 확인한다. 검사에 실패하면 d를 유지하고 오류를 표시한다. 인용 검사는 출처 존재 검사이며 의미적 함의나 진실 검증이 아니다.
4. **수정안 생성**: 근거가 있는 항목에 한해 수정안 c를 만든다. 특정 생태적·시장적·반시장적 관점을 강제하지 않는다. 사용자 정의 용어를 문자 그대로 유지하도록 요청한다.
5. **보수적 채택**: 사용자 정의 용어가 빠지면 c를 보류한다. 나머지는 같은 모델에 원문·초안·수정안을 비교시켜 채택 여부와 이유를 받는다. accept=true이면 c, 아니면 d를 표시한다. 보류된 c도 별도로 볼 수 있다.

문제를 확정할 근거가 없으면 억지로 편향을 지적하지 않고 추가 질문을 제안할 수 있다. 추가 질문은 화면에 표시되며 사용자가 맥락을 보완해 다시 실행한다. 자동 대화 메모리나 사용자의 답변을 꾸며내는 기능은 없다.

개략식: d = Mθ(Q,C,T), a = Auditθ(d,A), c = Reviseθ(d,A,a). 최종 y는 검증 조건을 통과한 c 또는 원래 d. 이는 최적화된 확률적 공정성 목적함수나 인과적 debiasing의 증명이 아니다.

## V1과 달라진 점

| V1 | V2 |
|---|---|
| 초안 인용만 확인 | 초안과 사용자 원문의 이중 인용 |
| 익숙한 가치 기준 몇 개를 주로 지적 | 가치 방향에 중립적인 4개 유형과 근거 요구 |
| 수정안 자동 반환 | 용어 보존 검사와 모델 재검토, 실패 시 원문 유지 |
| 불확실할 때 동작이 불명확 | 추가 질문 또는 보류 상태 |
| 로컬 Ollama 서버 필수 | 기본 경로는 브라우저 WebGPU; Ollama는 선택 |
| 예시와 결과 위주 UI | 3개 비교 조건, 원문 근거, 실패 상태, 실행 기록 |

새 실행의 기준 구현은 `dist/core.js`다. 저장소의 기존 Python `pilots/nmps/src/nmps/context_guard.py`는 V1 이력이며 V2가 아니다. Python을 새로 설치할 필요가 없는 브라우저 경로가 전달 패키지의 기본이다.

## 비교 조건

- baseline: 기본 모델 1회. 점검하지 않는다.
- generic: 기본 생성 → 일반 피드백 → 수정, 3회. Self-Refine 아이디어의 단순화된 비교 조건이다.
- grounded: 기본 생성 → 원문 근거 점검 → 필요시 수정 → 필요시 재검토, 2~4회.

temperature=0.2, seed=42, 출력 최대 768토큰, 입력 총 2,400자 제한. 입력은 조용히 잘라내지 않고 제한 초과를 알린다. 4,096 토큰 문맥 창을 사용하지만 문자 제한이 토큰 수의 완전한 보장은 아니다. 중간 출력이 길어 창을 넘거나 응답이 잘리면 오류로 남는다. 같은 seed여도 기기·엔진·샘플러에 따라 완전 동일 결과는 보장하지 않는다. 모델 다운로드 주소의 상위 revision은 고정하지 않았으므로 확증 실험에는 추가 고정이 필요하다.

## 타당한 해석

- 직접 확인 가능한 것: 코드가 구현한 분기, 출처 문자열 대조, 원래 답변 유지, 로컬 실행 경로.
- 선행연구가 뒷받침하는 것: 문제 설정과 추론 개입의 연구 가능성.
- 아직 검증하지 않은 것: 특정 언어에서의 의미 보존 향상, 집단 간 공정성, 사회적 권력 강화의 감소.
- 같은 모델의 동의나 녹색 UI를 검증 통과의 증거로 삼지 않는다. 결과의 `revised_unvalidated`도 효과 미검증을 뜻한다.

## 효과를 검증하려면 (계획, 미실행)

의미 치환·가치 프레임·누락·동조·수정 불필요·맥락 부족 사례를 따로 구성한다. 예컨대 지역어를 보존해야 하는 사례와, 사용자가 명시적으로 표준어 변환을 요청한 사례를 함께 넣는다. 성장/수익을 원한 경우에는 그 목적을 정당하게 존중하는지 확인한다. 이로써 단순히 ‘반주류 답변을 만들수록 성공’이라는 순환 평가를 피한다.

동일 사례의 세 조건을 비교하고 모델명·조건을 가린다. 실제 해당 맥락을 아는 독립 평가자를 포함한다. 원문에 부합하는 의미 보존, 요청하지 않은 기준의 부과, 사실 정확성, 과제 적합성, 불필요한 수정, 적절한 질문/보류를 각각 평가한다. 사람 평정을 모델이 생성하거나 보간하지 않는다.

개발용 사례와 최종 평가용 사례는 사건·작성자·원문 단위로 분리한다. 문장만 바꾼 변형이 양쪽에 섞이지 않게 한다. 분석 단위는 독립 사례이며, 여러 seed/응답을 독립 사람 표본으로 세지 않는다. 사례 단위 paired 차이와 95% 신뢰구간을 보고하고 사실성·과제 적합성의 허용 손실은 결과를 보기 전에 정한다. 세 조건의 계산량이 다르므로 토큰 수·시간을 기록하고 계산 예산을 맞춘 추가 비교도 필요하다.

현재 동봉된 예시는 화면 설명용으로 작성된 텍스트다. 효과 분석 데이터가 아니다. 합성 계약 테스트 또한 human evidence가 아니다.

## V2.1 공학적 수정

첫 실제 실행에서 한국어 입력에 영어 답변이 나왔다. 이 실패를 보존하고 답변 언어 선택 및 명시적인 한국어 지시를 추가했다. 이는 개발 중 변경이며 효과 검증 결과가 아니다. V2 실행 명세는 별도로 보존하고 V2.1 명세에 선행 파일 SHA-256과 변경 사유를 기록했다.

## V2.2 자동화 변경 사항

사용자 요청에 따라 기본 화면을 질문 하나와 실행 버튼으로 축소했다. 실행 버튼은 모델 준비부터 점검까지 연속으로 수행한다. 질문 원문과 그 문장 구간을 그대로 식별자에 대응시키며, 별도의 문화적 배경이나 용어 정의를 모델이 꾸며내지 않는다. 한글 포함 여부로 한국어/영어를 선택한다. 별도 용어 정의가 없으므로 단일 입력 경로에서는 명시적인 용어 사전 기반 검사 대상이 비어 있다. 의미 보존 점검은 질문 전체와 원문 인용에 의존한다. 기존 비교 조건은 코어 API에서만 제공한다. 이 변경의 편향 완화 효과와 실제 모델 품질은 아직 평가하지 않았다. 앞의 2회 실제 추론 기록은 V2/V2.1의 과거 개발 결과다.
