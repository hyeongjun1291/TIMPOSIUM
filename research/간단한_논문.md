# 언어 편중 완화를 위한 원문 근거 기반 LLM 추론 구조

## 초록

대규모 언어모델은 입력의 언어적 표현이나 가치 기준을 익숙한 범주로 치환할 수 있다. 본 연구는 이러한 언어 편중을 줄이기 위한 접근으로, 사용자 원문과 생성 응답을 대조하여 수정 여부를 결정하는 추론 구조를 제안한다. 제안 방법은 고정된 기반모델을 이용해 초안 생성, 원문 근거 점검, 수정안 생성 및 재검토를 수행한다. 점검 항목에는 초안과 원문의 인용을 모두 요구하며, 프로그램은 인용의 존재를 확인하고 조건을 충족하지 못한 수정안을 보류한다. Qwen2.5-Instruct와 WebLLM을 사용해 단일 입력으로 동작하는 로컬 구현을 구성하였다. 개발 검증에서는 17개 코드 테스트와 제한적인 실제 추론을 통해 실행 흐름을 확인했으나, 요청한 항목 수를 지키지 못하고 이를 점검에서 발견하지 못한 사례도 관찰되었다. 본 연구의 현재 기여는 원문 근거 검증과 보수적 채택을 결합한 추론 구조의 구현이며, 언어 편중 감소와 과제 성능 향상은 독립적인 비교 평가를 통해 검증할 과제로 남는다.

**주제어:** 언어 편중, 대규모 언어모델, 원문 근거, 추론 구조, 자기수정

## 1. 서론 및 관련 연구

언어 편중은 어떤 표현과 기준을 정상적인 기본값으로 취급하는지와 관련된다. Blodgett 외[1]는 NLP 편향 연구에서 피해와 언어적 위계의 정의를 분명히 할 필요를 제기하였다. Hofmann 외[2]는 방언에 따라 모델의 판단이 달라지는 현상을 보고했다. 본 연구는 이 문제를 요청하지 않은 표준화, 원문 의미의 손실, 표현 변이별 과제 성능 차이로 좁혀 다룬다. 한국어에서 동일한 효과가 이미 확인되었다고 가정하지 않는다.

Self-Refine[3]는 생성·피드백·수정을 통한 추론 단계 개입을 제시하지만, 자기수정은 항상 개선으로 이어지지 않는다[4]. 이에 본 연구는 수정 결과를 자동으로 정답으로 간주하지 않고 원문 근거 검사와 채택 조건을 둔다. 또한 다원적 정렬[5]과 동조 연구[6]를 참고해 사용자 의도 존중과 사용자 주장의 무조건적 승인을 구분한다.

## 2. 제안 구조

입력 x는 하나의 질문 문자열이다. 원문 전체와 문장 구간을 식별자 Q, S1, S2…에 대응시키며, 숨은 배경이나 용어 정의를 생성하지 않는다. 가중치 θ가 고정된 모델 Mθ를 사용하여 다음 절차를 수행한다.

**x → 초안 d → 근거 점검 a → 인용 검사 → 수정 후보 c → 채택 여부 v → 출력 y**

점검 유형은 의미 치환, 요청하지 않은 기준 부과, 명시된 맥락 누락, 근거 없는 확정이다. 각 항목은 d의 인용과 x의 인용·식별자를 포함한다. 프로그램은 두 인용이 해당 원문에 실제로 존재하는지 검사한다. 유효한 문제가 없으면 d를 유지하고, 유효한 문제가 있으면 c를 생성한다. 재검토 모델이 c를 승인하면 y=c, 거절하거나 처리에 실패하면 y=d이다. 초안 생성 자체가 실패하면 오류를 반환한다.

점검과 재검토는 같은 기반모델을 사용한다. 인용 존재 검사는 출처를 확인할 뿐 해석의 옳음을 보장하지 않는다. 현재 단일 입력 경로에는 별도 용어 사전이 없으므로, 명시적인 용어 사전 기반 보존 검사 대상도 없다. 신규 가중치 학습이나 독립 편향 분류기는 구현하지 않았다.

## 3. 구현

기본 모델은 Qwen2.5-1.5B-Instruct의 MLC 양자화 버전이며 WebLLM 0.2.85에서 실행한다. temperature는 0.2, seed는 42, 출력 한도는 768토큰, 문맥 창은 4,096토큰이다. 입력은 2,400자로 제한하며 초과분을 자동 삭제하지 않는다. 한글 포함 여부에 따라 한국어 또는 영어 출력 지시를 적용한다.

기본 생성은 1회, 일반 자기점검은 3회, 제안 방법은 2~4회의 모델 호출을 사용한다. 세 조건은 코어 API에 구현되어 있고 기본 실행 화면은 제안 방법을 사용한다. 실행 기록에는 원문, 출력, 점검 근거, 프롬프트와 호출 시간이 남는다. 화면의 추론 시간은 모델 호출 시간의 합이며 다운로드·로딩 시간은 제외한다. 모델 파일 revision과 기기별 차이를 완전히 고정하지 않아 확증 실험에는 추가적인 실행 환경 고정이 필요하다.

## 4. 개발 검증과 관찰

직접 확인한 근거는 `검증_기록.md`, `engineering_smoke.json`, 개발 저장소의 `tests/core.test.cjs` 및 `evaluation/protocol_context_guard_v2_2.json`이다. 인용 조작 거절, 오류 처리, 채택·보류 분기, 단일 입력 원문 보존 등을 확인하는 17개 코드 테스트가 통과했다. 이는 고정 응답을 사용하는 구현 검사이며 언어 모델의 성능 점수가 아니다.

기존 V2/V2.1에서는 동일한 소식지 질문을 두 차례 실행했다. 첫 응답이 영어로 나왔고 언어 지시를 보완한 후 한국어 응답이 생성되었다. V2.2에서는 질문 하나로 자동 모델 준비와 2회의 생성·점검 호출이 완료되었다. 다만 ‘방법 두 가지’를 요청했음에도 여섯 항목을 출력했고 점검은 문제를 발견하지 못했다. 따라서 자동 실행의 구현 가능성은 확인했지만 요청 준수와 점검 정확성은 제한적이다.

이 기록은 소수의 개발 실행이며 독립적인 확인 표본이 아니다. 편중 감소율, 효과 크기 및 신뢰구간을 계산하지 않았다. 새로 저장한 `논문기반_입력예시.md`의 8개 예시 묶음은 아직 평가하지 않은 합성 개발 입력이며, 본 절의 관찰 결과에 포함되지 않는다.

## 5. 평가 설계와 논의

후속 평가에서는 의미가 같은 격식체·비격식체 및 표준어·지역어 입력 쌍을 구성하고, 해당 표현을 이해하는 실제 화자가 의미의 동등성을 검토하도록 한다. 기본 모델, 일반 자기점검, 제안 방법을 비교하며, 요청하지 않은 표준화 비율, 의미 보존, 과제 정확성과 요청 준수, 점검 precision/recall, 실행 비용을 구분해 측정한다. 명시적으로 표준어 변환을 요청한 사례도 포함해 무조건적인 표현 보존을 성공으로 간주하지 않는다.

원문 인용 검사와 최종 재검토를 각각 제거하는 실험으로 구성요소의 기여를 분석할 계획이다. 이 제거 조건은 아직 구현·실행하지 않았다. 실제 평가자는 모델과 조건을 모른 채 채점하고, 의미가 같은 입력 쌍을 분석 단위로 paired 차이와 95% 신뢰구간을 보고한다. 언어 변이 간 격차가 줄더라도 양쪽의 절대 성능이 악화되면 성공으로 판단하지 않는다. 평가 자료와 판정 기준은 개발을 마친 뒤 결과 열람 전에 고정한다.

## 6. 결론

본 연구는 원문 인용 검증과 보수적 채택을 결합한 LLM 추론 구조를 구현하였다. 이 구조는 답변이 입력의 의미를 어떻게 반영했는지 추적하는 수단을 제공하지만, 자기점검만으로 언어 편중 감소를 보장하지는 않는다. 향후 연구의 핵심은 언어 변이별 성능 격차와 의미 손실을 독립적으로 측정하고, 추가 추론 비용에 비해 실질적인 개선이 있는지 확인하는 것이다.
