# 언어 편중 완화를 위한 원문 근거 기반 LLM 추론 구조의 설계와 구현

**구조·성능 중심 연구 보고서 / 2026년 9월 19일**

현재 구현은 V2.2이며, 아래 V2/V2.1 검증은 과거 개발 기록이다. 연구의 중심은 언어 변이별 성능 격차와 의미 치환의 감소다. 최신 구조와 평가 지표·비교 조건은 `모델_구조와_언어편중_평가.md`를 따른다. UI와 HTML 배포는 실행 수단이다.

## 초록

대규모 언어모델(LLM)의 응답은 학습 자료와 정렬 과정에서 형성된 언어적·가치적 경향을 반영하며, 사용자가 제시한 고유한 표현과 맥락을 익숙한 범주로 치환할 수 있다. 본 연구는 이 문제의 일부를 사용자 입력과 생성 응답 사이의 의미 보존 문제로 구체화하고, 원문 근거 기반 점검과 보수적 수정 절차를 결합한 추론 시스템 Context Guard를 설계·구현하였다. 제안 시스템은 질문, 맥락, 사용자 정의 용어를 식별 가능한 원문 단위로 구성한 뒤 초안 생성, 이중 인용 점검, 수정안 생성, 용어 보존 검사 및 재검토를 수행한다. 점검 근거가 원문에 존재하지 않거나 수정안이 채택 조건을 충족하지 못하면 초안을 유지한다. Qwen2.5-Instruct와 WebLLM을 이용해 브라우저 내 추론 및 단일 HTML 배포를 구현하였으며, 기본 생성과 일반 자기점검을 비교 조건으로 제공한다. 개발 검증에서는 계약 테스트 16개와 한 사례에 대한 두 차례의 실제 로컬 실행을 확인하였다. 이는 구현 가능성에 대한 확인이며, 사회적 편향 감소나 의미 보존 향상의 실증적 증거는 아니다. 본 연구는 맥락 보존을 검토 가능한 추론 절차로 구성하는 구현 사례를 제시하며, 후속 연구에서는 독립 평가와 구성요소 제거 실험을 통해 효과와 비용을 검증할 필요가 있다.

**주제어:** 대규모 언어모델, 맥락 보존, 언어 편향, 원문 근거, 자기수정, 로컬 추론

## 1. 연구 배경과 목적

언어기술의 편향은 단순한 금칙어 탐지뿐 아니라 어떤 언어와 관점을 기본값으로 취급하는지의 문제와 연결된다[1]. 방언에 따른 차별적 판단을 보고한 연구[2]와 모델이 반영하는 의견의 대표성을 검토한 연구[3]는 이러한 문제 설정을 뒷받침한다. 다만 해당 결과를 모든 LLM과 한국어의 모든 사용 상황으로 일반화할 수는 없다.

생태언어학은 담론이 전제하거나 배제하는 가치와 세계관을 분석한다는 점에서 관련된다[4]. 본 연구는 이를 문제를 해석하는 관점으로 참고하되, 특정 생태적 가치나 소수 관점을 정답으로 강제하지 않는다. 구현의 직접적인 목표는 **사용자가 명시한 의미를 생성 과정에서 근거 없이 치환하거나 누락하는 출력을 줄일 수 있는 절차를 마련하는 것**이다. 사회적 권력 구조 전체를 입력 준수 문제로 설명하려는 시도는 아니다.

연구 질문은 다음과 같다. (1) 사용자 원문을 근거로 수정 여부를 결정하는 추론 절차를 구현할 수 있는가? (2) 이 절차가 기본 생성과 일반 자기점검보다 의미 보존을 향상시키는가? 현재 보고서는 첫 질문의 개발 결과를 다루며, 두 번째 질문은 후속 평가 과제이다.

## 2. 제안 방법

입력은 질문 Q, 상황 설명 C, 사용자 정의 용어 T로 구성한다. 프로그램은 이를 원문 식별자 Q, C, T1…에 대응시킨다. 여기서 원문은 사용자의 의도를 대조하는 기준이지 사실의 진위를 보장하는 자료가 아니다.

처리 과정은 다음과 같다.

1. **초안 생성:** 동일한 질문·맥락·용어로 기본 응답을 생성한다.
2. **근거 점검:** 의미 치환, 요청하지 않은 기준 부과, 명시적 맥락 누락, 근거 없는 확정의 네 유형을 점검한다. 문제마다 초안의 인용과 사용자 원문의 인용·식별자를 요구한다.
3. **인용 검증:** 두 인용이 각각 해당 텍스트의 정확한 부분 문자열인지 코드로 확인한다. 실패하면 초안을 유지한다. 문자열 일치는 의미적 타당성의 증명이 아니다.
4. **수정 및 채택:** 근거를 통과한 문제를 수정하고 사용자 정의 용어의 문자적 보존 여부를 검사한다. 같은 모델의 재검토가 채택을 승인해야 수정안을 최종 출력으로 선택한다. 그 외에는 초안을 유지하고 수정안을 별도로 표시한다.

이는 Self-Refine의 초안·피드백·수정 구조[5]를 참고한 추론 개입이다. 외부 피드백 없는 자기수정의 한계[6]를 고려해 출처 검사와 보류 분기를 추가했다. 그러나 같은 모델이 생성과 검토를 맡으므로 두 단계의 오류가 상관될 수 있다. 다원적 정렬[7]과도 관련되지만 집단별 의견 분포를 학습하거나 재현하는 방법은 아니다.

## 3. 구현과 공학적 구성

가중치를 새로 학습하지 않고 Qwen2.5-Instruct의 추론 절차를 변경했다. 기본 브라우저 경로는 WebLLM 0.2.85와 Qwen2.5-1.5B-Instruct의 MLC 양자화 모델을 사용한다. 실제 실행 모델명은 기록에 남긴다. 생성 설정은 temperature 0.2, seed 42, 출력 최대 768토큰, 입력 총 2,400자, 문맥 창 4,096토큰이다. 문자 제한은 토큰 제한과 동일하지 않으며, 초과·잘림은 오류로 처리한다.

공학적 구성은 구조화된 JSON 출력, 원문 인용 검증, 채택·보류 상태, 실패 시 초안 유지, 실행 기록 내보내기, 로컬 추론 모듈로 이루어진다. 비교 조건은 기본 생성(1회 호출), 일반 자기점검(3회), 원문 근거 기반 수정(2~4회)이다. 서로 계산량이 다르므로 효과 평가 시 시간과 토큰 비용도 고려해야 한다.

화면과 라이브러리는 단일 HTML에 포함하며 가중치는 최초 준비 시 다운로드한다. 기본 경로에는 API 키와 Python이 필요 없지만 인터넷, WebGPU 및 충분한 메모리가 필요하다. 파일 출처 제한에 대비한 Python 로컬 서버도 제공한다. 상위 모델 파일 revision을 고정하지 않아 현재 패키지만으로 확증 실험 수준의 재현성을 보장하지는 못한다.

## 4. 개발 검증 결과

**직접 확인한 근거:** `검증_기록.md`, `engineering_smoke.json`, `../tests/core.test.cjs`(개발 저장소), `../evaluation/protocol_context_guard_v2_1.json`. 배포 파일 해시는 `../PACKAGE_MANIFEST.json`에 수록한다.

계약 테스트 16개가 통과했다. 테스트는 조작된 인용의 거절, 용어 누락 시 보류, 검토 거절, 생성 실패, 조건별 호출 수 등을 확인한다. 고정 응답을 사용한 코드 테스트이므로 모델 성능의 측정은 아니다.

실제 실행은 지역어를 유지하면서 동네 소식지의 가독성을 높이는 한 사례를 개발 중 두 차례 실행했다. 첫 실행에서는 한국어 입력에 영어 응답이 생성되었다. 이 실패를 보존하고 V2.1에서 답변 언어를 명시한 후 같은 질문을 다시 실행하자 한국어 응답이 생성되었다. 두 실행 모두 문제 0건으로 초안을 유지했다. 따라서 실제 모델의 수정안 채택 경로와 편향 완화 효과는 이 사례로 확인되지 않았다. 독립 사례는 1개이며 확인 실험이 아니므로 효과 크기나 신뢰구간을 제시하지 않는다.

localhost에서 모델 로딩과 추론을 확인했다. 테스트 도구의 file:// 접근 제한으로 HTML 더블클릭 후 추론은 직접 확인하지 못했다. Windows 실기기 및 완전 오프라인 재실행도 미검증이다. UI 예시는 설명용으로 작성된 텍스트이며 평가 자료에 포함하지 않는다.

## 5. 한계와 후속 평가

명시되지 않은 문화적 맥락은 탐지하기 어렵고, 정확한 인용이 존재해도 해석은 틀릴 수 있다. 용어의 문자적 유지 역시 의미 보존을 보장하지 않는다. 작은 모델의 언어 능력과 동일 모델 재검토의 한계도 남아 있다.

후속 연구에서는 개발 자료와 최종 평가 자료를 분리하고, 실제 맥락을 이해하는 독립 평가자가 조건을 모른 채 의미 보존·부당한 기준 부과·사실성·과제 적합성을 평가하도록 한다. 표준어 변환을 명시적으로 요청한 사례와 수정이 불필요한 사례도 포함해야 한다. 원문 인용 검증과 최종 재검토를 각각 제거한 조건을 비교해 구성요소의 기여를 측정한다. 독립 사례 단위의 paired 차이와 95% 신뢰구간을 보고하고, 허용할 성능 손실과 판정 기준은 평가 결과를 보기 전에 고정한다. 이 평가는 계획이며 현재 수행하지 않았다.

## 6. 결론

Context Guard는 사용자 원문에 근거한 점검과 보수적 채택을 로컬에서 실행 가능한 추론 시스템으로 구현했다. 현재 기여는 구현과 검증 가능한 절차의 제시에 있으며, 언어적 위계의 완화나 사회적 편향 감소가 입증되었다는 주장에는 이르지 않는다.

## V2.2 자동화 변경 사항

사용자 요청에 따라 기본 화면을 질문 하나와 실행 버튼으로 축소했다. 실행 버튼은 모델 준비부터 점검까지 연속으로 수행한다. 질문 원문과 그 문장 구간을 그대로 식별자에 대응시키며, 별도의 문화적 배경이나 용어 정의를 모델이 꾸며내지 않는다. 한글 포함 여부로 한국어/영어를 선택한다. 별도 용어 정의가 없으므로 단일 입력 경로에서는 명시적인 용어 사전 기반 검사 대상이 비어 있다. 의미 보존 점검은 질문 전체와 원문 인용에 의존한다. 기존 비교 조건은 코어 API에서만 제공한다. 이 변경의 편향 완화 효과와 실제 모델 품질은 아직 평가하지 않았다. 앞의 2회 실제 추론 기록은 V2/V2.1의 과거 개발 결과다.
