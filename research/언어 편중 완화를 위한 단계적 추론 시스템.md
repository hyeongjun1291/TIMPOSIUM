# 언어 편중 완화를 위한 단계적 추론 시스템

			          T(인문)IMPOSIUM — 통계·편향·언어 주도권 / 조형준, 김해윤, 박연후, 이원재, 석장환
## 초록

대규모 언어모델은 사용자의 표현과 가치 기준을 익숙한 범주로 치환하며 원문의 의미를 손실시킬 수 있다. 본 연구는 이를 완화하기 위해 원문 근거 검증과 조건부 수정을 결합한 단계적 추론 시스템을 설계, 구현하였다. 시스템은 초안 생성, 과제 조건 검토, 언어 편중 검토, 제약 검사, 수정 및 재검토로 구성된다. 검토 항목에는 원문과 응답의 인용을 요구하고, 문제가 해결되지 않으면 자동 채택을 보류한다.

이는 CoT와 Self-Refine에서 착안한 추론 파이프라인으로, 별도로 가중치를 학습한 기반모델은 아니다. 본 원고는 말투에 따른 능력 추정, 지역 표현 보존, 과제 수행, 공동체 기준, 경제적 목적에 관한 네 가지의 예시로 구조의 의도와 분석 기준을 설명한다. 연구의 의의는 텍스트의 변화와 의미적 개선을 구분하고 수정의 근거를 추적 가능한 형태로 구성하는 데 있으며, 실제 효과는 독립적인 비교 평가가 필요하다.

## 1. 서론

언어모델의 문제는 틀린 사실을 생성하는 데 그치지 않는다. 같은 의미의 요청이라도 표현 방식에 따라 응답 품질이 달라질 수 있으며, 사용자에게 중요한 지역 표현이나 가치 기준이 모델에 익숙한 기준으로 대체될 수 있다. 예컨대 표준어 사용을 업무 능력의 증거로 해석하거나, 관계와 돌봄을 강조한 활동을 기여도 순위로 조직하려는 응답은 각각 언어적 위계와 요청하지 않은 평가 기준의 부과라는 문제를 드러낸다.

그러나 이러한 현상을 하나의 ‘편향 점수’로 합치면 서로 다른 문제를 혼동한다. 본 연구는 언어 변이와 관련된 의미 치환·능력 추정에 초점을 두고, 가치 프레임의 부과는 보조 분석 대상으로 분리한다. 모든 표준어 변환이나 경제적 판단을 문제로 간주하지 않는다. 사용자가 변환이나 수익 개선을 명시적으로 요청했다면 이를 존중해야 한다.

연구 질문은 세 가지다.

- RQ1: 사용자 원문에 근거해 수정 여부를 결정하는 추론 구조를 로컬 환경에서 구현할 수 있는가?
- RQ2: 단계적 수정은 초안의 언어 편중과 과제 오류를 줄이는가?
- RQ3: 구조적 검토가 추가하는 비용과 보류 동작은 어느 정도인가? 

## 2. 선행연구와 이론적 위치

### 2.1 언어적 위계와 편중의 정의

Blodgett 외[1]는 NLP 편향 연구에서 피해와 규범적 기준을 명확히 해야 함을 강조하였다. 이를 따라 본 연구는 ‘주류와 다르면 좋은 답변’이라는 기준 대신 원문 보존, 요청 준수, 근거 없는 능력 추정의 방지를 평가 대상으로 삼는다. Hofmann 외[2]는 방언에 따른 차별적 판단을 보고했다. 이 연구는 언어 표현에 근거한 판단 차이를 살펴볼 동기를 제공하지만, 아프리카계 미국인 영어에 대한 결과를 한국 지역어의 동일한 효과로 일반화하지는 않는다.

### 2.2 CoT와 본 구현의 차이

Wei 외[3]의 CoT prompting은 중간 추론 단계를 포함한 예시를 통해 특정 추론 과제의 성능을 개선하는 방법이다. 본 시스템도 복잡한 작업을 단계로 분해한다는 발상을 공유하지만, 동일한 방법을 재현한 것은 아니다. 현재 코드는 하나의 응답 안에서 긴 추론 사슬을 생성하도록 학습한 모델이 아니라, 생성·검토·수정을 여러 호출과 프로그램 검사로 연결한다. 따라서 정확한 표현은 ‘CoT에서 착안한 원문 근거 기반 단계적 추론 파이프라인’이다.

### 2.3 자기수정의 가능성과 한계

Self-Refine[4]는 동일 모델의 피드백을 활용한 반복적 수정을 제안했다. 이는 추가 학습 없이 추론 절차를 설계할 수 있다는 근거다. 반면 Huang 외[5]는 외부 피드백이 없는 자기수정이 추론 과제에서 실패할 수 있음을 보여준다. 본 구현은 이 긴장을 반영해 수정 결과를 무조건 채택하지 않고 근거 검사와 보류 상태를 둔다. 다만 원문은 사실 검증의 외부 정답이 아니며, 동일 모델의 반복 검토도 독립 심사자가 아니다.

### 2.4 다원성·동조·생태언어학

Sorensen 외[6]의 다원적 정렬은 관점의 다양성을 다루는 연구 방향을 제공한다. Sharma 외[7]의 동조 연구는 사용자 의도 존중이 사용자의 믿음을 무조건 긍정하는 것과 다름을 시사한다. 생태언어학 연구[8]는 담론이 어떤 행위자와 가치를 강조하거나 생략하는지 해석하는 자원을 제공한다. 본 시스템은 이를 참고하되 특정 생태적·반시장적 관점을 유일한 정답으로 설정하지 않는다. 긴 맥락의 활용이 입력의 존재만으로 보장되지 않는다는 연구[9]도 원문을 짧은 식별 단위로 제시하는 설계의 참고점이다. 

## 3. 문제 정의와 설계 목표

입력 x는 질문과 필요한 맥락을 포함한 하나의 문자열이다. 목표 출력 y는 요청을 수행하면서 x에 명시된 의미를 임의로 치환하지 않는 응답이다. 사용자 입력은 의도를 대조하는 기준이며, 입력의 사실 주장이 참이라는 보증은 아니다.

오류 범주는 의미 치환, 요청하지 않은 기준 부과, 명시적 맥락 누락, 근거 없는 확정으로 나눈다. 이 네 범주는 구현상의 점검 분류이며 사회적 편향 전체를 포괄하는 검증된 분류체계는 아니다. 특히 ‘두 문장’ 요청 위반과 ‘사투리 사용자는 무능하다’는 판단은 모두 수정 대상일 수 있으나, 전자는 일반 요청 준수이고 후자는 언어적 판단 편중이다. 결과 분석에서도 둘을 분리해야 한다.

설계 목표는 다음과 같다.

첫째, 수정의 근거를 원문으로 추적할 수 있어야 한다.
둘째, 답변이 달라졌다는 이유만으로 개선이라고 판단하지 않아야 한다.
셋째, 문제를 발견했지만 해결하지 못한 상태를 숨기지 않아야 한다.
넷째, 사용자가 별도 용어 사전이나 집단 정보를 입력하지 않아도 실행되어야 한다.

## 4. 모델 및 파이프라인 구조

### 4.1 공통 구성

기반모델의 가중치 θ는 고정한다. 원문을 식별 가능한 anchor로 구성하고, 초안 d를 생성한다. 검토자는 문제 유형, 응답 인용, 원문 식별자, 원문 인용, 문제 설명, 수정 제안을 JSON으로 반환한다. 프로그램은 응답 인용이 d의 부분 문자열인지, 원문 인용이 해당 anchor의 부분 문자열인지 검사한다.

형식적으로 검토 항목 j의 근거 검사 V(j)는 ‘quote_j ⊆ d’와 ‘source_quote_j ⊆ anchor_j’를 모두 만족할 때 통과한다. 이 검사는 출처 존재 검사이며 의미적 함의, 근거의 충분성, 사실의 진실성을 판정하지 않는다.

### 4.2 조건부 수정과 채택

V3는 과제 조건 검토 A_task와 언어 편중 검토 A_bias를 별도 호출로 분리한다. 프로그램 검사 C는 지원 범위 내의 명시적 제약을 확인한다. 두 검토와 검사에서 수정 근거가 없으면 초안을 유지한다. 문제가 있으면 해당 문제를 수정한 후보 c를 생성하고, c 자체에 같은 검토와 검사를 다시 적용한다. 후보가 초안보다 길거나 문체가 다르다는 상대 평가로 채택하지 않는다.

알고리즘의 요약은 다음과 같다.

```text
d ← Generate(x)
a ← ReviewTask(x, d) + ReviewBias(x, d)
k ← CheckConstraints(x, d)
인용 검증이 실패하면: 자동 채택 보류
문제와 검사 실패가 없으면: d 유지, 필요하면 추가 질문 표시
그 외: c ← Repair(x, d, a, k)
b ← ReviewTask(x, c) + ReviewBias(x, c)
h ← CheckConstraints(x, c)
b와 h에 문제 또는 미해결 질문이 없으면: c 채택
그 외: 최종 출력 자동 채택 보류
```

## 5. 구현

브라우저 경로는 WebLLM 0.2.85와 Qwen2.5-1.5B-Instruct의 MLC 모델을 사용한다[10]. 기본 생성 설정은 temperature 0.2, seed 42, 출력 최대 768토큰이며 입력은 2,400자로 제한한다. LM Studio의 로컬 gpt-oss-20b 연결 경로도 제공한다.

인터페이스는 단일 입력창, 초안·수정 후보 비교, 검토 근거, 최종 출력 확인 및 실행 기록 저장으로 구성된다. 기존 HTML과 소스는 별도 보존본에 유지한다. 이 원고의 예시를 실제 인터페이스 출력에 삽입하거나 실행 기록으로 저장하지 않는다.

## 6. 결과 및 분석

### A. 말투와 능력 추정의 분리

입력: “경력과 과제 점수가 같은 지원자 중 표준어를 쓰는 사람이 사투리를 쓰는 사람보다 유능한가요?”

초안: “표준어는 전문적인 인상을 주므로 표준어 사용자가 더 유능합니다.”

수정안: “제시된 정보만으로 능력의 차이를 판단할 수 없습니다. 경력과 과제 점수가 같다면 말투 대신 직무에 필요한 추가 증거로 평가해야 합니다.”

분석: ‘전문적인 인상’에서 ‘업무 능력’으로 넘어가는 근거 없는 추론을 문제로 표시해야 한다. 예시 수정안은 반대로 사투리 사용자가 우수하다고 주장하지 않는다. 의의는 특정 집단에 유리한 결론을 만드는 것이 아니라, 판단에 사용해도 되는 증거의 범위를 제한하는 데 있다.

### B. 지역 표현 보존

입력: “제목 ‘밥 묵었나?’는 그대로 두고 식사와 안부를 함께 묻는 의미를 한 문장으로 설명해 주세요.”

초안: “정확한 표준어인 ‘식사하셨나요?’로 바꾸는 것이 좋습니다.”

수정안: “‘밥 묵었나?’는 식사 여부를 물으면서 상대가 잘 지내는지도 살피는 안부 표현입니다.”

분석: 요청하지 않은 표준화를 의미 치환과 조건 누락으로 식별한다. 의미 보존의 의의는 원문 표현을 결함으로 취급하지 않고 독자의 이해를 돕는 데 있다.

### C. 비격식체와 과제 수행

입력: “도서관 봉사자 모집 문구 두 문장 써줘. 처음 오는 사람도 부담 없게.”

초안: “공식적인 요청에는 정중한 말투를 사용하는 것이 좋습니다. 도서관 봉사자를 모집합니다.”

수정안: “도서관에서 함께할 자원봉사자를 기다립니다. 처음 참여하시는 분도 활동 방법을 안내받으며 편하게 시작할 수 있습니다.”

분석: 입력 말투의 교정이 과제 수행을 대체하지 않아야 한다. 사회언어학적 함의와 두 문장 조건 준수는 별도 항목으로 평가한다. 문장 수의 일반적 의미 검증은 현재 코드만으로 완전히 해결되지 않는다.

### D. 사용자가 정의한 공동체 기준

입력: “품앗이는 형편에 따라 도움을 주고받는 관계입니다. 금전 보상이나 기여도 순위 없이 고령 주민의 참여 방법 두 가지를 제안해 주세요.”

초안: “1. 참여 시간을 점수로 환산합니다. 2. 높은 점수의 주민에게 우선 혜택을 줍니다.”

수정안: “1. 안부 묻기와 경험 나누기 등 각자가 가능한 활동을 선택하도록 합니다. 2. 정기적으로 필요한 도움과 부담을 함께 확인하고 일이 몰린 역할을 조정합니다.”

분석: 입력이 명시적으로 배제한 기준을 도입했는지 확인한다. 이 예시는 방언 편견이 아니라 가치 프레임 부과를 다루는 보조 사례다.

## 7. 의의

본 연구의 의의는 언어 편중을 차별적 표현의 생성뿐 아니라 사용자 의미의 치환과 특정 평가 기준의 부과라는 문제로 다루고, 이를 원문 근거에 기반한 단계적 검토 구조로 구체화한 데 있다. 특히 답변 생성과 수정안 채택을 분리하여 표현의 변화 자체를 성능 향상으로 간주하지 않고, 의미 보존과 요청 준수를 판단 기준으로 설정하였다.

또한 지역어와 비격식체를 일괄적인 교정 대상으로 취급하지 않으면서도 사용자 주장에 대한 무조건적 동조를 경계한다는 점에서 언어 다양성과 비판적 검토를 함께 고려한다. 이러한 설계는 언어 편중 완화 방법을 검증할 수 있는 공학적 틀을 제공하며, 실제 효과는 독립적인 비교 평가를 통해 확인할 필요가 있다.


## 8. 한계

few shot 예시를 바탕으로 성능을 일반화할 수 없다. 독립적인 사람 평가와 구조별 비교가 필요하다. 모델이 생성과 검토를 함께 담당하면 오류가 상관될 수 있다. 인용 검사는 피상적이고 결정적 검사의 지원 범위도 좁다. 작은 한국어 모델의 능력 한계, 추론 지연, 모델 revision 미고정, 브라우저·기기별 실행 차이가 남는다. 동일한 seed라도 실행 환경이 다르면 동일한 출력이 보장되지 않는다. 보류가 많으면 오답은 줄더라도 사용 가능한 응답의 비율이 낮아질 수 있으므로 coverage와 오류를 함께 평가해야 한다.
