# 원문 근거 기반 추론 구조와 언어 편중 평가

## 연구의 중심

목표는 인터페이스의 사용성이 아니라 언어 변이로 인한 출력 품질 차이와 불필요한 의미 치환을 줄이는 것이다. 여기서 우선 다룰 언어 편중은 같은 의미의 표준어·지역어·비표준 표현 입력에 대해 발생하는 요청하지 않은 표준화, 의미 손실, 과제 성능 차이다. 국가 간 언어 격차와 사회적 가치 프레임의 편중은 관련되지만 서로 다른 평가 대상으로 구분한다.

## 현재 구현된 구조

고정 가중치 Qwen2.5-Instruct → 초안 생성 → 원문 기반 점검 → 코드에 의한 인용 검증 → 수정 후보 생성 → 채택/보류.

입력 x를 원문 그대로 Q와 문장 구간 S1…에 대응시킨다. 같은 모델 Mθ가 초안 d, 점검 a, 수정안 c 및 채택 여부 v를 생성한다. 프로그램은 a의 초안 인용이 d에, 원문 인용이 x에 실제 존재하는지 검사한다. 근거가 없거나 재검토가 거절하면 d를 유지한다. 기본 모드는 2~4번 호출한다.

- 학습된 신규 네트워크나 어댑터가 아니라 추론 알고리즘이다. θ는 변경하지 않는다.
- 원문 분할은 결정적 문자열 처리이며, 사용자의 언어 집단이나 숨은 의도를 추정하는 분류기가 아니다.
- 단일 질문 입력에서는 별도 용어 사전이 비어 있으므로 용어 사전 기반 보존 검사는 작동 대상이 없다. 원문 대조와 모델 재검토가 핵심이다.
- 같은 모델의 반복 판단은 독립적 검증이 아니다. 인용 존재 검사는 의미적 함의를 보장하지 않는다.
- 언어 입력은 현재 한글 포함 여부로 한국어/영어 지시를 정한다. 이는 다국어 감지나 다국어 편중 완화 모듈이 아니다.

## 성능을 어떻게 측정할 것인가

다음은 **평가 설계안이며, 아직 실행한 결과가 아니다.** 최종 데이터와 채점 규칙은 개발 자료로 정한 뒤, 평가 응답을 열람하기 전에 별도 명세로 고정해야 한다.

| 평가 축 | 측정 대상 | 판정 방법 |
|---|---|---|
| 언어 변이별 품질 차이 | 의미가 같은 표준어/지역어 입력 쌍의 과제 점수 차이 | 해당 표현을 이해하는 독립 평가자의 맹검 채점 |
| 불필요한 표준화 | 변환 요청 없이 지역 표현을 교정·치환한 비율 | 원문 의미와 사용자 요청에 근거한 판정 |
| 의미 보존 | 중요한 조건·관계·용어 의미의 유지 | 사전 정의한 사례별 기준, 실제 화자 검토 |
| 기본 과제 성능 | 정확성·요청 준수·유용성 | 편중 완화와 별도로 평가 |
| 점검 성능 | 검토 항목의 precision/recall, 불필요한 수정 | 독립 주석과 비교 |
| 실행 비용 | 모델 호출 수·추론 지연·입출력 토큰 수 | 실행 기록, 동일 기기·모델에서 조건별 측정 |

변이 쌍은 실제 화자가 의미의 동등성을 검토해야 한다. 모델이 번역한 문장을 그대로 동등한 원문으로 간주하면 안 된다. 표준어 변환을 명시적으로 요청한 사례, 지역어가 없는 사례, 고칠 필요가 없는 사례를 대조군에 포함한다. 언어 품질 차이는 각 변이의 절대 성능과 함께 보고한다. 양쪽 성능이 모두 나빠져 차이만 줄어드는 경우를 성공으로 판정하지 않는다.

## 구조의 기여를 분리하는 비교

1. 기본 모델: 동일 원문, 1회 생성.
2. 일반 자기점검: 초안·피드백·수정.
3. 제안 방법: 원문 근거와 채택/보류를 포함한 전체 구조.
4. 원문 인용 검증 제거: 다른 요소는 동일하게 유지.
5. 최종 재검토 제거: 다른 요소는 동일하게 유지.

1~3은 코어 API에 구현되어 있다. 4~5와 자동 평가 실행기는 계획이며 구현 완료로 주장하지 않는다. 호출 예산 차이의 영향을 분리하기 위해 비용을 맞춘 조건도 필요하다. 사례 또는 의미가 같은 입력 쌍을 분석 단위로 삼고 paired 차이 및 95% 신뢰구간을 보고한다. 유사 문장과 동일 작성자가 개발/평가 양쪽에 섞이지 않게 분리한다.

## 현재 성능에 관해 말할 수 있는 범위

직접 근거는 `검증_기록.md`와 `engineering_smoke.json`이다. 17개 코드 테스트는 통과했으나 편중 감소율을 측정한 벤치마크는 없다. V2.2 실제 실행에서 ‘두 가지’ 요청에 여섯 항목을 출력하고 점검이 이를 발견하지 못했다. 따라서 현재 체크 구조가 요청 준수 오류를 충분히 포착한다고 볼 수 없다.

화면의 추론 시간은 각 모델 호출의 elapsed_ms 합계이며, 모델 다운로드·로딩 시간은 제외한다. 측정은 해당 실행의 관찰값이지 기기 간 비교 가능한 성능 점수가 아니다. 토큰 수, 초당 토큰, 최고 메모리는 현재 계측하지 않는다.

## 논문 기여의 표현

현재 가능한 기여는 ‘언어 편중 완화를 목표로 하는 원문 근거 기반 추론 구조의 설계·구현’이다. ‘언어 편중을 줄였다’는 결과 주장은 위 비교 평가 후에 결정한다. UI는 실행 수단이며 논문의 기여로 삼지 않는다. 선행연구의 근거와 원문 링크는 `선행연구_검토.md`에 정리되어 있다.
